# Preview Builder (Next.js + Flask + SQLite)

Multi-tenant “preview builder” for dealership websites:
- **Flask dashboard** to create/update brand configs and upload media
- **SQLite (`app/data/previews.db`)** as the single source of truth for brand configs
- **Next.js app** renders the correct brand per-request based on the request domain/host

## What’s in this repo

- `app/` — Next.js app (site + APIs)
- `app.py` — Flask dashboard + JSON API for previews
- `templates/`, `static/` — Flask dashboard UI
- `app/data/previews.db` — SQLite DB storing preview configs (JSON per brand)
- `app/data/inventories/` — per-brand inventory JSON files
- `public/images/` — uploaded brand assets (logo/hero/favicon, etc.)
- `proxy.ts` — Next.js proxy (replaces deprecated middleware convention)

## How it works (high level)

1. You create or edit a preview (brand) in the Flask dashboard.
2. Flask persists the full brand config as JSON in `previews.db`.
3. Next.js loads the brand **at runtime** by calling Flask’s API (no rebuild required).
4. Brand selection is based on the incoming request host (supports custom domains).

## Multi-theme previews

Preview configs can now select a complete Next theme via `theme.id` / `themeId`.

- Contract source: `app/themes/<theme-id>/` (filesystem contract)
- Auto-generated catalog: `theme/theme-manifest.json` (generated by `npm run theme:sync`)
- Flask catalog endpoint: `GET /api/themes`
- Next runtime theme resolution: request host -> preview config -> generated theme registry
- `/create` UI supports theme selection beside domain and inside AI generator

Theme registries and manifest are generated automatically on `npm run dev` and `npm run build`.

Full reference:
- [`docs/multi-theme-preview-system.md`](docs/multi-theme-preview-system.md)

## Quick start (local dev)

### 1) Install and run Next.js

```bash
npm install
npm run dev
```

Next runs on `http://localhost:3000`.

### 2) Install and run Flask dashboard/API

**Python 3.12 is required.** Pillow 10.1.0 and cryptography 42.0.8 only ship
prebuilt wheels through 3.12; on 3.13/3.14 `pip install` falls back to
building from source which needs MSVC + libjpeg + Rust + OpenSSL.

```bash
# Windows — use the launcher to pick 3.12 explicitly
py -3.12 -m venv venv
venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py

# Linux/macOS
python3.12 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Flask runs on `http://localhost:5000`.

You can also use the helper scripts (they handle the venv + the 3.12 pin):
- Windows: `start.bat`
- Bash/WSL/macOS/Linux: `start.sh`

If you've already created a `venv/` with the wrong Python version, delete it
(`rmdir /s /q venv` on Windows, `rm -rf venv` on Linux/macOS) and re-run.
The start scripts detect and warn about a mismatched venv.

## Environment variables

Next.js reads `.env` and uses these commonly:

- `FLASK_API_URL` or `NEXT_PUBLIC_FLASK_API_URL`
  - Base URL for the Flask API.
  - Default: `http://localhost:5000/api`
- `NEXT_PUBLIC_SITE_URL`
  - Used by some features (emails, links).
- `BRAND_CACHE_TTL_MS`
  - Optional in-memory cache TTL for brand config lookups.
  - Default `0` (no caching; always fresh).
  - If you want caching, set e.g. `BRAND_CACHE_TTL_MS=60000` (60s).

## Brand (preview) storage

- Database: `app/data/previews.db`
- Table: `previews`
  - `slug` (primary key)
  - `name`
  - `config` (JSON string, full brand config)
  - `created_at`, `updated_at`

Important conventions:
- **Theme colors are stored in `theme.colors`** (source of truth).
- Uploaded assets are saved into `public/images/` and the config stores paths like `/images/{slug}-logo.png`.

## Brand resolution (domain → preview)

On each request, Next determines the brand using:

1. `x-brand` (injected by `proxy.ts` when available)
2. **Domain lookup** against the DB via Flask: `GET /api/previews/resolve?host=...`
3. Host-based fallback: first subdomain segment (e.g. `citimotors.local:3000` → `citimotors`)

This design is what allows **new previews to be visible in production without rebuilding Next.js**—as long as Next can reach the Flask API at runtime.

## Inventory per brand

Inventory is loaded from JSON files in:
- `app/data/inventories/{brandSlug}-inventory.json`

If a brand inventory file is missing, the app may fall back to `app/data/inventory.json` (depending on the API route logic).

## Deployment notes

Recommended production layout:
- Run **Next.js** and **Flask** as separate processes/containers.
- Ensure Next can reach Flask via `FLASK_API_URL`.
- Ensure your reverse proxy forwards host headers (`Host`, and ideally `x-forwarded-host`).
- The GitHub deploy workflow runs `python app.py --init-previews-db` before
  rebuilding/restarting, so idempotent preview schema changes are applied on deploy.

If you deploy to an environment with an immutable filesystem (common in serverless),
do **not** rely on “editing the bundled `previews.db`” at runtime. Instead, run Flask with persistent storage and let Next read configs via the Flask API.

## Dealer preview gate

Dealer subdomains under `*.carouspreviews.co.uk` automatically use the preview
gate. The default policy is 24 hours total view time and unlimited visits. Control it
per preview by storing this on the brand config:

```json
"previewGate": {
  "enabled": true,
  "maxViewSeconds": 86400,
  "maxVisits": 0,
  "expiresAt": "2026-05-20T18:00:00Z",
  "status": "active"
}
```

Set `maxViewSeconds` or `maxVisits` to `0` for unlimited. Set `status` to
`"locked"` to manually lock a preview. The remote creation helper also supports
`--preview-minutes`, `--preview-seconds`, `--preview-visits`,
`--preview-expires`, `--preview-unlimited`, and `--preview-locked`.

## Common troubleshooting

- “Preview only updates after rebuild”
  - Confirm Next is fetching from Flask at runtime (`FLASK_API_URL`).
  - Ensure `BRAND_CACHE_TTL_MS` is unset or `0` while debugging.
- “Wrong brand on first request / localhost fallback”
  - Ensure host headers are forwarded by your proxy.
  - Confirm the brand’s `domain` is correct in the stored preview config.
- “Blocked cross-origin request … /_next/*”
  - For local multi-domain dev, configure `allowedDevOrigins` in `next.config.js`.
