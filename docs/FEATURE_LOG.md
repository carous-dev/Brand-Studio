- 2026-05-07: Fix brand-site reload-after-a-moment bug (owner: Difatha)
  - Scope: `app/themes/context-registry.ts`, `app/layout.tsx`, `next.config.js`
  - Reason: Brand-site visitors reported a hard refresh (white flash, same URL, no console errors) firing 5–60s after page load, in both dev and deployed environments. Root causes traced to two issues: (1) `context-registry.ts` imported `./editorial-showroom/context/{...}` from a directory that does not exist in the repo, which made the layout module fail to compile in dev (and produced an inconsistent server bundle in prod that could trigger Next.js's silent deployment-mismatch hard-reload on `<Link>` prefetch); (2) `app/layout.tsx`'s `generateMetadata` injected `Date.now()` into the favicon URL on every server render, which combined with `dynamic = 'force-dynamic'` made the metadata non-deterministic across requests — another known trigger for Next.js's RSC payload mismatch hard-reload.

    - Removed dead `editorial-showroom` imports + registry entry (only `classic-dealer` and `gilded-drive` exist on disk).
    - Stripped `Date.now()` cache-buster from the server-side favicon metadata (the `DynamicFavicon` client component still updates `<link rel=icon>` hrefs at runtime when the brand changes, so cache-busting remains where it belongs).
    - Removed bogus `dynamicMetadata = 'force-dynamic'` export — not a recognised Next.js export.
    - Replaced obsolete `experimental.turbo.excludeFiles` with empty `turbopack: {}` stub. The legacy `webpack.watchOptions.ignored` block is no longer relevant under Next 16's default Turbopack — Turbopack only re-runs HMR for files in the import graph, so writes to `app/data/**`, `*.db`, `public/images/**` (which Flask makes) don't trigger reloads.
